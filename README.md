# Парсер заявок Profi.ru по автоматизации

Серверное приложение следит за новыми заказами на Profi.ru, отбирает заявки
по разработке ботов, CRM, парсеров и автоматизации и отправляет подходящие
заказы в Telegram.

Основной вариант эксплуатации — Linux-сервер без графического интерфейса.
Chromium работает в headless-режиме, а первичная и повторная авторизация
выполняются через SMS-код, который пользователь отправляет Telegram-боту.

## Быстрый запуск на Linux

Рекомендуется Ubuntu или Debian с Python 3.10+ и systemd. Запускайте проект от
обычного отдельного пользователя, не от `root`.

### 1. Загрузите проект на сервер

Перейдите в его папку:

```bash
cd /путь/к/Profi.ru_Parser_Bot
```

### 2. Установите приложение

```bash
bash install.sh
```

Скрипт:

- создаст виртуальное окружение `.venv`;
- установит Python-зависимости;
- проверит по базе OSV всё дерево зависимостей проекта, включая транзитивные пакеты;
- установит Chromium и Linux-библиотеки Playwright;
- сохранит существующий `.env` или создаст его из примера;
- закроет доступ других пользователей сервера к `.env`.

На Ubuntu/Debian установщик Playwright может запросить пароль `sudo` для
системных библиотек. Если не удаётся создать окружение, выполните:

```bash
sudo apt update
sudo apt install -y python3 python3-venv
bash install.sh
```

### 3. Настройте `.env`

```bash
nano .env
```

Обязательные значения:

```dotenv
BOT_TOKEN=токен_telegram_бота
PROFI_LOGIN=+79990000000
```

Ограниченный режим, рекомендуемый для рабочего сервера:

```dotenv
ADMIN_CHAT_ID=числовой_id_вашего_чата
```

Если оставить `ADMIN_CHAT_ID=` пустым, включается открытый режим: ботом может
пользоваться любой человек, написавший ему в личный чат. Групповые чаты при
этом не принимаются. Каждый пользователь после `/start` сохраняется в
`data/telegram_chats.json` и получает заявки и служебные уведомления.

Открытый режим менее безопасен: любой подписчик сможет запускать `/renew`,
отправлять SMS-код и отменять восстановление. Защита от частых запросов SMS
ограничивает `/renew` одним запуском в пять минут, но для рабочего аккаунта
лучше всё же указать `ADMIN_CHAT_ID`.

Перед первым запуском откройте бота в Telegram и нажмите **Start** или
отправьте `/start`. Telegram не разрешает боту первым начинать диалог.

Серверные настройки должны оставаться такими:

```dotenv
HEADLESS=true
SESSION_RECOVERY_ENABLED=true
SESSION_RECOVERY_HEADLESS=true
```

Если сервер должен подключаться к Telegram через локальный Naive/SOCKS5:

```dotenv
TELEGRAM_PROXY=socks5://127.0.0.1:20808
PROFI_PROXY=direct
```

`TELEGRAM_PROXY` применяется только к Telegram. Основной Chromium и браузер
восстановления сессии запускаются с `--no-proxy-server` и используют обычный
канал Raspberry Pi. Адрес `127.0.0.1:20808` подходит, когда Naive/SOCKS5
запущен на этом же сервере.

Чтобы намеренно направить Chromium через отдельный прокси, укажите его полный
адрес в `PROFI_PROXY`. Значение `direct` закрепляет обычное подключение.
Если проверка через `socks5h://` обрывается, а через обычный `socks5://`
работает, задайте `TELEGRAM_PROXY_RDNS=false` — Telegram останется на SOCKS,
но DNS-имя будет разрешать Raspberry Pi.

`bash check.sh` проверяет, что указанный адрес и порт прокси действительно
доступны, а затем выполняет реальный запрос к Telegram API через этот прокси.
Проверка останавливается с понятной ошибкой, если порт открыт, но сам прокси
сбрасывает соединение. Для проверки SOCKS5 вручную используйте
`curl --proxy socks5h://127.0.0.1:20808 -I https://api.telegram.org`, а для
HTTP-прокси — `curl --proxy http://127.0.0.1:20808 -I https://api.telegram.org`.

### 4. Проверьте установку

```bash
bash check.sh
```

Отсутствие `data/storage_state.json` до первого запуска не считается ошибкой:
бот создаст сессию через SMS.

Отдельно проверить реальную изоляцию BrowserContext на локальном стенде:

```bash
.venv/bin/python app.py session-audit
```

Команда не обращается к Profi.ru и проверяет cookies, localStorage,
sessionStorage, IndexedDB, Cache Storage, Service Workers, permissions,
стабильность browser environment и закрытие всех созданных контекстов.

### 5. Выполните первый тестовый запуск

```bash
bash start.sh
```

Если сохранённой сессии ещё нет:

1. Бот дождётся поля `auth_login_input` и введёт в него `PROFI_LOGIN`.
2. Подождёт 1 секунду, не нажимая никакие кнопки.
3. Не будет нажимать кнопку, пока она показывает «Продолжить» или МТС ID.
4. Дождётся, когда `[data-testid="enter_with_sms_btn"]` стабильно получит текст
   «Войти по сим-пушу или СМС», повторно проверит его и только затем нажмёт.
5. Profi.ru отправит владельцу аккаунта SMS, а бот попросит код в Telegram.
6. Отправьте боту только цифры кода обычным сообщением.
7. Бот создаст `data/storage_state.json` и автоматически запустит парсер.

Для остановки тестового запуска нажмите `Ctrl+C`.

## Постоянная работа и автозапуск

Установите пользовательский systemd-сервис:

```bash
bash service.sh install
```

Чтобы сервис продолжал работать после закрытия SSH и запускался после
перезагрузки сервера, один раз включите linger для текущего пользователя:

```bash
sudo loginctl enable-linger "$(whoami)"
```

Управление сервисом:

```bash
bash service.sh status   # состояние
bash service.sh logs     # журнал в реальном времени
bash service.sh restart  # перезапуск после обновления файлов или .env
bash service.sh stop     # остановка
bash service.sh start    # запуск
```

Приложению не нужны входящие порты. Серверу требуется исходящий HTTPS-доступ
к `profi.ru` и `api.telegram.org` либо к указанному Telegram-прокси.

## Уведомления о состоянии

Бот уведомляет администратора либо всех подписчиков открытого режима, когда:

- Profi.ru несколько раз подряд не показывает карточки заказов;
- браузер или страница завершаются с ошибкой;
- авторизованная сессия закончилась;
- работа сайта восстановилась;
- достигнут лимит автоматических перезапусков.
- сервис запущен, остановлен или обновлён до новой версии;
- heartbeat перестал обновляться или давно не было успешной проверки;
- на сервере заканчивается свободное место;
- обнаружена CAPTCHA или страница ограничения доступа.

Сообщение об ошибке отправляется после `SITE_ERROR_THRESHOLD` последовательных
сбоев, по умолчанию после трёх. Одинаковые сообщения не создают спам.

## Автоматическое обновление cookies

При завершении сессии парсер останавливается, бот запускает чистый headless-
контекст Chromium и запрашивает новый SMS-код. После успешного входа новый
файл cookies записывается сначала во временный файл, а затем атомарно заменяет
`data/storage_state.json`. Парсер возобновляется автоматически.

Код:

- принимается только из `ADMIN_CHAT_ID`, а в открытом режиме — из любого
  зарегистрированного личного чата;
- должен содержать ровно 4 цифры;
- не сохраняется в файлах и журналах;
- ожидается 5 минут, если не изменён `SMS_CODE_TIMEOUT_SEC`.

Повторный ручной запрос `/renew` защищён интервалом
`RECOVERY_COOLDOWN_SEC`, по умолчанию 5 минут.

Команды бота:

| Команда | Назначение |
| --- | --- |
| `/status` | состояние cookies и процедуры восстановления |
| `/health` | Telegram, Chromium, Profi.ru, heartbeat, cookies и диск |
| `/version` | установленная версия проекта |
| `/renew` | вручную запросить новую сессию через SMS |
| `/cancel` | отменить ожидание SMS-кода |
| `/resume` | продолжить после CAPTCHA или блокировки |
| `/help` | показать справку |

Если Profi.ru изменит форму входа или форма зависнет, бот отправит
диагностический скриншот в Telegram. PNG, HTML страницы и точный этап ошибки
сохраняются в `logs/debug/session_recovery_failed.*`. По умолчанию поле
SMS-кода определяется по точному атрибуту
`data-testid="auth_pin_input"`. Локатор можно переопределить через
`PROFI_OTP_SELECTOR` без изменения Python-кода.

Бот просит код в Telegram сразу после успешного перехода на этап подтверждения
Profi.ru. Полученный ответ должен состоять ровно из четырёх цифр. Если SMS
пришла раньше, чем поле успело отобразиться, отправлять её боту ещё нельзя:
бот принимает код только после собственного запроса для текущей формы. Старые
и присланные заранее коды очищаются и не переносятся в следующую попытку.
Перед запросом кода бот дожидается единого OTP-поля. Поиск поддерживает как
`data-testid="auth_pin_input"`, так и видимое поле без специальных атрибутов,
которое Profi.ru оформляет четырьмя линиями. Поле очищается от автозаполнения,
после чего четыре цифры вводятся последовательными клавиатурными событиями с
постоянным интервалом. Клавиша Enter не используется: отправку выполняет сама
форма Profi.ru.

Во время восстановления бот сначала ждёт и заполняет поле телефона. Локатор
кнопки до ввода номера не сохраняется. После ввода бот проверяет только
`[data-testid="enter_with_sms_btn"]`, но сначала выдерживает паузу 1 секунду без
каких-либо кликов. Затем бот ждёт несколько последовательных проверок, на которых
текст остаётся «Войти по сим-пушу или СМС». Состояния
«Продолжить» и МТС ID никогда не нажимаются. Непосредственно перед единственным
кликом текст, видимость и доступность проверяются ещё раз. Поиск по ролям,
перебор кнопок, ручной список и запасные клики отсутствуют. При несовпадении
восстановление останавливается с диагностикой.

На каждом этапе входа бот также проверяет текст страницы. Если Profi.ru показывает
«Слишком много попыток. Можно будет повторить через 12 часов», бот сохраняет
окончание паузы в `data/site_cooldown.json`, закрывает браузер и полностью
прекращает обращения к сайту. Таймер переживает перезапуск сервиса. По окончании
12 часов вход и парсер возобновляются автоматически; `/renew` и `/resume` не
могут снять это ограничение раньше срока.

Telegram начинает принимать SMS-код сразу после перехода на этап подтверждения.
До ответа пользователя бот вообще не ищет поле кода и не взаимодействует с ним.
Получив ровно четыре цифры, бот выдерживает отдельную паузу 1 секунду, впервые
ищет видимое поле `data-testid="auth_pin_input"`, после его обнаружения ждёт ещё
1 секунду и только затем вставляет код одним действием. Форма на этом этапе
автоматически не перезагружается.
Поиск выполняется во всех открытых вкладках и iframe, а CSS-локаторы Playwright
также проходят через открытые shadow DOM. Если `data-testid="auth_pin_input"`
установлен на оболочке компонента, бот использует вложенный редактируемый `input`.
Поле всегда ищется после ответа пользователя, поэтому перерисовка React или
замена iframe во время ожидания кода не оставляет у бота устаревший элемент.

`TELEGRAM_PROXY` применяется только к Telegram. Chromium по умолчанию работает
напрямую. Для отдельного прокси Chromium укажите в `PROFI_PROXY` полный адрес
вида `socks5://127.0.0.1:20808`. Резервные маршруты рекомендуется записывать в
`data/profi_proxies.txt`: один полный адрес на строку, пустые строки и строки с
`#` игнорируются. Путь можно изменить через `PROFI_PROXY_POOL_FILE`. Переменная
`PROFI_PROXY_POOL` по-прежнему позволяет добавить адреса через запятую;
значение `direct` в любом источнике означает прямое подключение.

По умолчанию первый запуск идёт через `PROFI_PROXY`. Чтобы сразу начать работу
через первый адрес из файла, укажите `PROFI_PROXY_START_FROM_POOL=true`. Если пул
пуст или отсутствует, настройка безопасно игнорируется и используется
`PROFI_PROXY`.

Для отказоустойчивого случайного выбора маршрута при каждом новом запуске
процесса укажите `PROFI_PROXY_RANDOM_ON_START=true`. Эта настройка имеет
приоритет над `PROFI_PROXY_START_FROM_POOL` и выбирает только реальные прокси,
исключая `direct`. Внутренний перезапуск Chromium после сетевой ошибки сохраняет
выбранный маршрут и постоянную browser identity. Случайный выбор не гарантирует,
что два последовательных запуска не выберут один и тот же адрес.

Chromium и стартовый HTTP-сеанс используют одну сохраняемую browser identity:
User-Agent, Client Hints, locale, timezone и viewport. Identity хранится в
`data/chromium-profile/profi-browser-identity.json`; в лог попадают только её
короткий ID, viewport, точный профиль `curl_cffi` и количество cookies — без их
значений. Перед первым открытием страницы cookies Chromium переносятся в
`curl_cffi`, а полученные `Set-Cookie` возвращаются в Chromium. Значение
`PROFI_HTTP_IMPERSONATE=chrome` автоматически выбирает профиль, совпадающий с
версией из `PROFI_USER_AGENT` (`chrome136` для настройки по умолчанию).

BrowserContext создаются централизованно через `BrowserSessionManager`. Менеджер
учитывает активные session ID, умеет закрыть оставшиеся контексты и журналирует
ошибки cleanup. Есть два
явных режима хранения состояния:

- `fresh` — новый контекст без унаследованных cookies и site storage;
- `authenticated` — контекст с загрузкой `data/storage_state.json`.

Обычное закрытие или перезапуск Chromium не удаляет авторизацию и browser
identity. Полная очистка выполняется только явным вызовом
`ProfiClient.purge_session_state()`. Ручная авторизация, SMS-восстановление и
основной парсер используют один профиль locale/timezone/viewport/User-Agent.
Каталог содержит обычный профиль `profi_desktop` и отдельный профиль
`profi_desktop_moscow_geo` с разрешением geolocation и координатами Москвы.

После первого открытия доски в журнал записывается JSON `browser_snapshot`:
browser/API-сигналы, названия cookies и storage-объектов без их значений. Модуль
`browser_sessions.py` также предоставляет сравнение снимков и аудит утечек между
двумя свежими контекстами. Реальные Chromium-тесты проверяют cookies,
localStorage, sessionStorage, IndexedDB, Cache Storage, Service Workers и
permissions, а также одновременную работу нескольких независимых контекстов.

Stealth-настройки согласуют `navigator.webdriver`, `platform`, `languages` и
`userAgentData`. При 12-часовом ограничении identity, cookies и IP не меняются:
проект соблюдает показанный сайтом срок и не создаёт новые попытки входа.

Если на странице появляется точная надпись «Можно будет повторить через 12
часов», парсер сохраняет диагностику, закрывает Chromium и включает обязательную
паузу ровно на 12 часов. Telegram-бот остаётся доступен, `/status` и `/health`
показывают оставшееся время, а после завершения таймера парсер запускается сам.
Это отличается от CAPTCHA: 12-часовая пауза не снимается командой `/resume`.

## CAPTCHA, безопасная пауза и heartbeat

Парсер распознаёт характерные URL, заголовки, тексты и видимые элементы
CAPTCHA, а также HTTP 403. В таком случае он:

1. сохраняет PNG, HTML и Playwright trace;
2. отправляет скриншот в Telegram;
3. полностью завершает браузерный процесс;
4. не обращается к Profi.ru до команды `/resume`;
5. после `/resume` выполняет одну обычную повторную проверку.

CAPTCHA автоматически не решается. Если ограничение осталось, парсер снова
перейдёт на безопасную паузу.

Отдельный heartbeat обновляется независимо от цикла браузера. Watchdog
уведомляет о двух разных состояниях: процесс перестал подавать признаки жизни
или процесс жив, но страница заказов давно не проверялась успешно. После
восстановления отправляется только одно сообщение без повторного спама.

## Защита от лишней нагрузки и блокировок

Парсер согласует техническую browser identity, но не решает CAPTCHA и не
гарантирует отсутствие блокировок. Ротацию IP используйте только для маршрутов
и аккаунта, для которых у вас есть разрешение; автоматическая ротация не
отменяет правила Profi.ru.

Для снижения нагрузки реализованы безопасные меры:

- запросы выполняются с непостоянным интервалом 90–150 секунд;
- при последовательных ошибках пауза экспоненциально растёт до 15 минут;
- ответы HTTP 403, 429 и 5xx не вызывают агрессивные повторные запросы;
- учитывается числовой заголовок `Retry-After`, если сайт его прислал;
- повторные аварийные запуски процесса также замедляются;
- одинаковые уведомления объединяются и не создают спам;
- автоматический вход выполняется только при завершении сессии.
- второй экземпляр с тем же каталогом данных не запускается.

Гарантировать отсутствие блокировки сторонним сайтом невозможно. Самый
надёжный вариант — использовать официальный API или письменное разрешение
владельца сайта, если такие варианты доступны.

## Фильтр целевых заявок

Прежние правила исходного проекта сохранены в `filters.py`. Заявка принимается,
если одновременно выполнены условия:

- найдена тематика ботов, CRM, парсеров или автоматизации;
- в тексте есть намерение разработать, настроить, внедрить или интегрировать;
- заявка не относится к рекламе, таргетингу, SMM и исключённым платформам;
- явно указанный бюджет составляет не менее 10 000 ₽.

Если бюджет в тексте не указан, заявка не отклоняется только по этой причине.
Исключения всегда имеют приоритет над целевыми словами.

Проверить произвольный текст на сервере:

```bash
.venv/bin/python app.py filter "Нужно разработать CRM, бюджет 50 000 рублей"
```

## Рабочие файлы

```text
data/
├── storage_state.json       # cookies Profi.ru
├── seen_ids.json            # уже обработанные заявки
├── new_orders.jsonl         # очередь подходящих заявок
├── bot_cursor.json          # позиция отправщика Telegram
├── system_events.jsonl      # события сайта и сессии
├── system_event_cursor.json # позиция отправщика событий
├── telegram_chats.json      # подписчики открытого режима
├── heartbeat.json           # признаки жизни и последняя успешная проверка
├── site_cooldown.json        # окончание обязательной 12-часовой паузы
├── version_state.json       # версия для уведомления об обновлении
└── parser.lock              # блокировка второго экземпляра

logs/
├── parser.log
├── bot.log
├── run_all.log
└── debug/

backups/
└── safe-backup-YYYY-MM-DD.json
```

`.env`, cookies, данные заказов, список чатов и журналы получают права `600`,
а рабочие каталоги — `700`. Они также исключены из Git. Ежедневная безопасная
копия содержит фильтры и несекретные настройки, но намеренно исключает токен,
логин, прокси и cookies. Сессию на новом сервере следует пересоздать через
`/renew`.

Очереди JSONL автоматически обнуляются после полной доставки и достижения
порогового размера. `seen_ids.json` хранит временные метки, удаляет старые
записи и ограничивает максимальный размер. Старые PNG, HTML, trace и резервные
копии удаляются по сроку хранения. Ротация обычных логов выполняется отдельно.

## Диагностика

```bash
bash check.sh
tail -n 100 logs/parser.error.log
tail -n 100 logs/bot.error.log
tail -n 100 logs/run_all.error.log
.venv/bin/python audit_dependencies.py
```

Если Telegram или Profi.ru недоступны, проверьте общий прокси и значение
`TELEGRAM_PROXY`. Если сайт изменил форму входа, отправьте `/renew`, затем
посмотрите `logs/debug/session_recovery_failed.png`.

При CAPTCHA используйте `/health`, изучите присланный скриншот и отправьте
`/resume` только после того, как ограничение могло быть снято. Trace открывается
командой `.venv/bin/playwright show-trace путь/к/файлу.trace.zip`.

скрипты, `HEADLESS=true` и systemd.
